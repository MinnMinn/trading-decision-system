---
title: Round 3b of the 2026-09-24 Wyckoff label review (narrative-authoring/checking contract + invalidated-label rendering) is methodology-interpretation significant
date: 2026-09-24
status: ACCEPTED
context: docs/audits/2026-09-24-wyckoff-label-review.md answered a six-point external critique of the published CFD Scalping XAUUSD 15m Wyckoff chart with book-cited verdicts (SUPPORTED / PARTLY SUPPORTED / NOT IN THE BOOK / CONTRADICTED) and six proposal groups (P1-P6) plus a seventh section on rendering an already-invalidated label (P7.1-P7.4). Round 3a (parallel agent) owns P7.4 (the `wyckoff_bias` gate in scripts/htf_context.py) and the three backtest-side files (scripts/wyckoff_rules.py, scripts/backtest-methods.py, scripts/strategy-runner.py). This ADR covers everything else the review proposed -- the narrative-authoring contract, the checker, and the invalidated-label chart rendering (P7.1-P7.3).
problem: The narrative schema and scripts/check-narrative.py let an LLM-written Wyckoff read claim a Spring/SOS/LPS/Phase without recording the deterministic facts the book itself uses to test that claim (WMT volume type, WA p150 đối nhãn Dấu hiệu 1, R11's commitment-bars SOS test, the book's own "?" candidate convention). The 2026-09-11 XAUUSD read passed the checker that existed then while failing five of the book's own tests the review re-derived by hand. Separately, once a label's own invalidation condition has since fired (a later close beyond the Spring low), the chart kept drawing the dead structure's TR/phase/anchor lines to the right edge as if it were still current, and the read matrix kept showing its original verdict chip with no marker that the structure died on 2026-09-15.
decision: Extend the narrative schema with optional structured fields (events[].event_class/volume_type/volume_kind, wyckoff.doi_nhan{st_sign,phase_b_sign}, wyckoff.alternative, wyckoff.nesting, phases[].status) and encode nine new deterministic checks in scripts/check-narrative.py (P1.1, P1.2, P2.1, P3.1, P4.1, P4.2, P5.1, P6.1, P6.2), reusing scripts/wyckoff_rules.py's own volume-type thresholds and lookback/commitment-bar constants rather than re-deriving them. Compute the invalidation time for a chart's own overlays AT BUILD TIME from the scanner's existing `first_close_beyond` fact (scripts/build-artifact.py invalidated_at()), never stored in the narrative file itself, and truncate/fade/mark the affected chart overlays and read-matrix cell in scripts/chart.js and build-artifact.py accordingly. Treat this as methodology-interpretation significant (CLAUDE.md §59) rather than Trading-System-version significant, because Wyckoff is engaged in no live style today (docs/architecture/automation-config.json) -- the narrative CONTRACT changes, but no live decision does.
alternatives:
  - Re-implement each deterministic check from scratch inside check-narrative.py instead of reusing scripts/wyckoff_rules.py's constants (VOL thresholds, COMMIT, PARAMS["lookback"]).
  - Store `invalidated_at` inside the narrative file once computed, so it does not need recomputing on every build.
  - Make `phases[].status` and `wyckoff.alternative` hard-required by the JSON Schema (via `required`) rather than by the checker.
  - Treat round 3b as Trading-System-version significant immediately, bumping every style's version.
chosen_approach: Reuse scripts/wyckoff_rules.py's constants (read-only import, no edits to that file); compute `invalidated_at` at build time from data/live/prelim/<style>.facts.json's existing anchors.levels[].first_close_beyond (already computed by scripts/ict-scan.py's anchor_facts()) and never persist it; enforce the new required-in-spirit fields (alternative, doi_nhan.st_sign, phases[].status) in the CHECKER, not the schema's `required` list; leave every style's version at whatever round 3a's ADR leaves it.
reason: Duplicating scripts/wyckoff_rules.py's thresholds would silently drift the first time either file's constant changed (CLAUDE.md §58 "duplicated domain rules"); reading them keeps one source of truth per rules/single-source-of-truth.md. Storing `invalidated_at` in the narrative would violate CLAUDE.md §17's immutability of an original expectation/label -- the file that says "Spring[C] 4,289.57" at `updated: 2026-09-11T15:00:00Z` must never gain a field describing something that happened on 2026-09-15; deriving it at build time from the scanner's own facts keeps the derivation point-in-time and reproducible without mutating the record. A hard JSON-Schema `required` on `alternative`/`doi_nhan`/`phases[].status` would break EVERY pre-round-3b narrative file's schema validity retroactively (there is no migration step for historical files, and CLAUDE.md §17 forbids rewriting them); the checker enforces the contract going forward on the specific fields it can compute or that a genuinely new read must supply, without asserting historical files were malformed when written. No Trading System today has Wyckoff as REQUIRED_FOR_DECISION (docs/architecture/automation-config.json shows every CFD/FX market's `wyckoff` dimension analysis-only or off), so §59's "potentially Trading System version significant" test is not met; it becomes significant only if/when a preset promotes Wyckoff to engaged, which is a separate, explicit decision.
consequences: Every daily-full headless prompt (integrations/headless/{scalping,cfd-scalping}-daily-full.md) now instructs the model to record event_class/volume_type/volume_kind, doi_nhan, alternative, nesting, phases[].status and the "?" candidate convention -- the NEXT full analysis for each style will produce narratives carrying these fields; historical narratives (including the reviewed 2026-09-11 XAUUSD read) do not and are not retroactively edited (§17). Running check-narrative.py against that historical narrative today reports the same defects the review found by hand (doi_nhan.st_sign missing, SOS[D]/LPS[D] unconfirmed at write time, wyckoff.alternative missing, phases[].status missing, tick-volume-as-sole-validator, wyckoff.nesting missing, and the context Wyckoff-vs-ICT bias contradiction the synthesis never named) -- this is expected and is itself the verification that the checker now encodes the review's findings, not a regression to fix. The chart's Wyckoff overlays (TR lines, phase bands, method anchors, the invalidation line) and the read-matrix's layer-3 cell now render an invalidated read as historical (fade + "hết hiệu lực/invalidated <date>" suffix, an x-mark on the breaking candle, a struck-through verdict chip) whenever `data/live/prelim/<style>.facts.json`'s own anchors show the level closed beyond after the narrative's `updated` -- verified end-to-end against the REAL (unmodified) cfd-scalping narrative, facts, and anchors files in this worktree via a monkeypatched candle source (scripts/build-artifact.py's own `candles()` has no live data to read from in this sandboxed worktree; the underlying `invalidated_at()`/`wyckoffShapes`/`levelShapes`/`planShapes` logic that renders it is exercised directly, unmodified, by scripts/tests/test_audit_round3_labels.py). Replay stays point-in-time with no additional cursor plumbing: `wyckoffShapes`/`levelShapes` compute `idxOf(rows, invalidatedAt)` against whatever ROWS the caller actually passed, and `applyLane`'s replay slice already stops short of the break until the reader's own cursor reaches it. P6.2's phase-band `status` defaults to `hypothesis` (dashed, lower alpha, "?" suffix) whenever a narrative omits the field -- a defensible default per CLAUDE.md priority order (safety over convenience: an unverified claim shown at full visual weight is a false claim about certainty), which means every PRE-round-3b narrative's phase bands now render at hypothesis weight until the next full analysis supplies `status: "tested"`.
rejected_alternatives:
  - Re-deriving volume/spread/commitment thresholds locally in check-narrative.py -- refused; scripts/wyckoff_rules.py already owns them and importing keeps one source of truth (rules/single-source-of-truth.md).
  - Persisting `invalidated_at` in the narrative file -- refused; violates CLAUDE.md §17 (original expectations/labels are immutable) and would need a migration/versioning story this round does not need.
  - Hard-`required` schema fields for alternative/doi_nhan/phases[].status -- refused; would mark every historical narrative file schema-invalid retroactively with no migration path, which the checker's softer (and citable) refusal avoids.
  - Bumping any live style's Trading System version now -- refused; no style engages Wyckoff as REQUIRED_FOR_DECISION today (§59's test is not met), and round 3a's P7.4 (the bias-gate fix) is the part of this review that IS version-significant for Wyckoff-engaging presets, tracked separately in that agent's own ADR.

## What round 3b implemented

**Narrative contract (docs/architecture/schemas/narrative.schema.json), all fields optional at the schema level, enforced by the checker where the review specifies:**
- `events[].event_class`, `events[].volume_type` (1/2/3), `events[].volume_kind` ("traded"|"tick") — P1.1/P5.1.
- `wyckoff.doi_nhan.{st_sign, phase_b_sign}` (WA p150-159, đối nhãn Dấu hiệu 1/2) — P1.1.
- `wyckoff.alternative` (WA2-27, the competing reading) — P6.1.
- `wyckoff.nesting` (WA2-19/20, where this range sits inside the HTF one) — P4.2.
- `phases[].status` ("tested" | "hypothesis") — P6.2.
- Documented "?" candidate convention for LPS/BU/LPSY/Test/SOS/SOW event labels — P2.1/P3.1.

**scripts/check-narrative.py, new functions (all covered by scripts/tests/test_audit_round3_labels.py):**
- `context_spring_checks` (P1.2) — a context-timeframe Spring/UTAD must actually cross the context trading_range border, checked from the narrative's own two numbers.
- `doi_nhan_and_spring_checks` (P1.1) — volume_type presence + agreement with the ratio computed from candles; the Spring/Shakeout bar's own close must be back above trading_range.low (a close above trading_range.high in the same bar is a WARNING, not a failure — the book has no rule for a one-bar Spring-plus-breakout); doi_nhan.st_sign required, and "contradicts" blocks the phase from advancing past C without `alternative` AND the synthesis naming the contradiction.
- `confirmation_grammar` (P2.1/P3.1) — `sos_confirmed()` replicates R11's test (close beyond TR, spread/volume ≥ lookback average, `commitment_bars` consecutive completed closes beyond) restricted to candles at or before the narrative's own `updated`; `pullback_confirmed()` is a documented, narrower project simplification for LPS/BU/LPSY/Test (WA p84-85's "demand pushes price back up" proxy, not a full R8/R11 replication). An event that fails or cannot yet be told must end its label in "?", or the checker refuses it.
- `alternative_and_status_checks` (P6.1/P6.2) — `wyckoff.alternative` required whenever a read exists; `phases[].status` required, and "tested" requires that phase's own confirming event to exist AND be confirmed (no trailing "?").
- `tick_volume_checks` (P5.1) — on a tick-volume feed (`instruments.is_tick_volume`), refuses "hợp lệ vì khối lượng ..." as a sole validator and requires a "(tick)" marker on every printed ratio.
- `phase_grammar` (existing function, extended) — a `?`-suffixed event is tracked separately (`seen_confirmed`) from a plain one (`seen`); Phase C/D's own "has no test event" / "has no SOS/LPS/BU" checks now also fire when the ONLY qualifying event is an unconfirmed candidate — "a '?' event cannot open a phase" (P3.1).
- P4.1/P4.2 wired directly into `main()`'s existing context block: both HTF reads' bias is computed independently via `htf_context.wyckoff_bias`/`ict_bias` (read-only calls into round 3a's file, no edits to it) and a disagreement must be named in the synthesis; `wyckoff.nesting` is required whenever a context read exists.

**Invalidated-label rendering (§7, P7.1-P7.3):**
- `build-artifact.py invalidated_at(n3, fsym)` — matches the narrative's `invalidation.level` against `data/live/prelim/<style>.facts.json`'s own `anchors.levels[].first_close_beyond`, returning a time only when it postdates the narrative's `updated` (point-in-time guard, CLAUDE.md §8). Never writes the narrative file.
- `scripts/chart.js` `wyckoffShapes`/`levelShapes`/`planShapes` — truncate the TR line, phase bands, Wyckoff-method anchor lines and the invalidation line at the breaking candle, fade them, append a "hết hiệu lực/invalidated <date>" suffix, mark the breaking candle with an x, and relabel the invalidation line "đã kích hoạt/triggered <date>". Replay stays point-in-time because `idxOf` is computed against whatever `rows` the caller passed (already sliced to the replay cursor upstream) — no separate cursor plumbing needed.
- `build-artifact.py matrix()` — the layer-3 verdict chip renders struck through plus "đã vô hiệu/invalidated <date>" and the structure badges gain a "(<date>, hết hiệu lực/invalidated)" suffix, once `invalidated_at()` returns non-None. The model's own prose is never touched.
