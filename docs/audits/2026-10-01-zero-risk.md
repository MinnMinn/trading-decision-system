# Zero-risk candidates under B-EX=fill: root cause, counts, fix (2026-10-01)

Branch `b18-zero-risk` (from `windows-migration` 3cc3ba2). Counts only: no R, expectancy or performance figure was read or
printed. Coordinator decision, owner to ack before `declare` (`docs/plans/2026-09-30-owner-decisions.md`, pre-registration
item 12).

## 1. Root cause

With the ICT V value `B-EX=fill` the entry is the far edge of the FVG (`scripts/ict-scan.py:687` long `"fill": f["lo"]`,
`:720` short `"fill": f["hi"]`); the stop is the extreme of the bars from the reference bar to the MSS bar
(`:689` long `min(L[ref_i:m["i"] + 1])`, `:722` short `max(H[...])`). A bull FVG's far edge `f["lo"]` is the HIGH of the gap's
first candle (`ict-scan.py:255`), so entry == stop whenever that candle is a flat (H == L) bar sitting at the sweep extreme, or
more generally whenever its high equals the extreme low of the range. `risk = entry - stop` is then 0 and `R` becomes `None`
(`:737`, `R = round(reward / risk, 2) if risk > 0 else None`), but `setup_candidate` still returns `complete: True`, and
`_ict_candidate` (`backtest-methods.py:1105`) does not look at `R`.

Why it reaches the engine: `fvg_fill` (`backtest-methods.py:684`) documents the invariant "For a long, stop < edge always
(risk = entry-stop > 0)" (docstring of `fvg_fill`, `backtest-methods.py:692`) -- false for `fill`. With entry == stop the first bar that
reaches the edge also reaches the stop, so `fvg_fill` returns `filled_and_stopped`, and `_ict_trade` books the pessimistic -1R
record directly (`backtest-methods.py:1197-1203`, `R_planned=su.get("R")` = `None`), bypassing `walk()`, whose
`if r <= 0: return None` (`:572-573`) is what drops such a trade on every other path. `real_costs.cost_r` then raises
`CostRefused("stop distance is zero")` (`real_costs.py:303` before this change, `:315` now), and the flat-fee path divides by zero
(`dist = abs(entry - stop) / entry`). In the harness `BtEngine.trades_for` prices every raw candidate before `simulate()`, so a
`run` aborts at the first value set that holds one.

Concrete case (US500 1m, 2023-03-07): bar 06:54Z `O=H=L=C=4053.5, V=1` is the sweep extreme and the first candle of the FVG
(`lo = 4053.5`, `hi = L(06:56) = 4053.8`); MSS bar 06:56; entry = stop = 4053.5; trade `entry_time` 07:00Z. Pinned by
`scripts/tests/test_zero_risk_admission.py::IctProducerSide`.

Why only `fill` yields exactly zero: `iofed` (near edge `f["hi"]`) and `ce` put the entry strictly inside the gap, above the
first candle's high >= its low >= the range minimum, so entry > stop; a stop buffer (`B-BUF`) lowers the stop. Live never sets
`fx_` keys (`iofed`), so live cannot produce it. Wyckoff cannot: the spring/phase-D legs require `target > C[last] > stop`
(`backtest-methods.py` `_fires_from`) and `walk()` drops risk <= 0. The data bear this out (section 2): zero-risk candidates
occur only in `B-EX=fill` value sets; a few positive-but-sub-tick risks also occur (mostly `fill`, 2 under `ce`: an FVG one
tick wide puts `ce` half a tick above the stop; older history carries prices finer than today's tick, not investigated further).

## 2. Count tables

Method: `scripts/research/zero_risk_count.py` (research script, wraps the harness `BtEngine.prefetch`, counts RAW scanned trades
-- exactly what `trades_for` feeds to `cost_r`/`simulate` -- by `classify()`), run on the frozen parent code (`git archive`
of 3cc3ba2) over the whole development span (PIT cutoff 2024-03-01) of every declared symbol/timeframe, summarised by
`scripts/research/zero_risk_table.py`. Value sets: ICT = baseline + all 26 single-factor sets (the harness' wave 1) + B-EX=fill
combined with every other single-factor value (the shape combined/perturbation sets take): 51 sets per symbol, sharing 2
analysis groups. Wyckoff = the sets of the baseline detection group (baseline, W-STOP=spring_low, W-MGMT=be, W-SPT=ceiling,
W-SPT=VAH, W-TOUCH=on) on the 1m cells; every single-factor set (14, all detection groups) on the 5m cell. Not enumerated: the
full cartesian product, the harness' data-dependent combined set and perturbation sets (the root cause says a set contains
the case iff it has `B-EX=fill`; every `fill+X` pair is in the table, and no non-fill set in it has a zero-risk row).
`entry_time` year; categories: `zero` (entry == stop), `wrong_side` / `negative`, `sub_tick` (0 < risk < tick), `invalid_price` /
`non_finite`. A category/set absent from a row group has 0. "(15 sets)" etc. means that many value sets have the identical
per-year row (the sets differing only in B-EXIT / B-POOL / B-MGMT / B-BUF=0 ... which do not change entry or stop).

## 3. The fix

* `scripts/backtest-methods.py` `planned_risk_refusal(side, entry, stop, tick=None)` (module level, before `simulate`): the one rule.
  Returns None for a placeable order, else `invalid_price` (entry/stop not finite, entry <= 0, unknown side), `zero`
  (entry == stop), `wrong_side` (stop on the profit side), `sub_tick` (0 < risk < tick, relative slack 1e-6).
  Without a tick only risk > 0 is asked.
* `simulate()` calls it first for every candidate (tick = `real_costs.tick_size(cost_profile, symbol)`, the spec's
  `tick_size`; none without a cost profile). A refused candidate is counted `SIM_LAST["refused"]["zero_risk"]` (by cause in
  `SIM_LAST["zero_risk_by_cause"]`), never priced (so no `CostRefused` / ZeroDivisionError), never entered, never in the
  one-position-per-symbol slot, never an R.
* `scripts/real_costs.py` `tick_size(profile, symbol)`: refuses (CostRefused) a spec with no positive `tick_size`.
* `scripts/fund-search.py` `BtEngine.trades_for`: builds its admission rows with the same function (a refused candidate is a
  `{"entry_time", "zero_risk": cause}` row, never priced); asserts it agrees with `simulate()`'s count (fail loud);
  `admission_stats` returns `refused_zero_risk` (counted in `candidates`, excluded from the min_rr margins), per fold and per value
  set; the report prints a "planned-risk admission" line next to the min_rr line.
* `ict-scan.py` is NOT changed (it is shared with live; `iofed` there cannot produce it).

Live parity: the rule is a shared function of `backtest-methods` (live already imports it for `fvg_fill`); the live runner is
unchanged (it never sets `fx_b_ex`, so `iofed`; a zero stop distance is refused there already by `risk_model.size`). Not wired into
`strategy-runner.py` -- out of scope; follow-up if the owner wants the guard on the `r_planned` division at
`strategy-runner.py:922` too.
