# Erratum — the 180 prop-search records (2026-09-28)

**Scope:** all 180 sealed §42 experiment records under `docs/experiments/prop-search-2026-09-27/records/`
(`plan_hash` `8137a8b1a76ce16118519037fd9baf77449bfc51c6c5f807c52c42df08b2028d`,
`docs/experiments/prop-search-2026-09-27/plan.json`). This erratum is a *disclosed correction* per
CLAUDE.md §42 ("Experiment records must be immutable") — no record file under `records/` is edited. It is
filed under item A0b of `docs/plans/2026-09-28-methodology-improvement-plan.md`.

## Why `experiment.py`'s own successor mechanism (`decide()`) was not used

`scripts/experiment.py`'s only successor writer, `decide()`, requires `actor == "human"` (case-insensitive)
and one of the §42 decision values `APPROVED` / `REJECTED` / `DEFERRED` — it exists to record a *human*
accept/reject judgement on a candidate, not a data-correctness note, and it is not authored by an AI agent
(CLAUDE.md §41: "AI must NEVER silently rewrite the production Trading System"; forging `actor: "human"` here
would itself be a §42 honesty violation of the kind this erratum exists to fix). This markdown file is the
documented fallback the A0b task authorized when no successor mechanism fits.

## What was checked, and what the finding actually is

The dispatching context for this task stated that all 180 records carry `ict_target: "range"` as a false
target-model label. **That specific claim was checked against the files and is not accurate as stated:**
every one of the 180 records' `configuration_snapshot.fields.setup.ict_target` is `null`
(`scripts/prop-search.py`'s call to `snapshot.backtest_config_snapshot()`, prop-search.py:653-655, never
passes `ict_target=`, so it is honestly absent in every sealed record — verified by loading all 180 files and
checking the field). The file that *does* carry `run_params.ict_target: "range"` and
`config_snapshot.fields.setup.ict_target: "range"` as a misleading label is a different artifact family:
`data/history/stability/*.json` (produced by `scripts/stability-report.py`, whose `--ict-target` CLI default
is `"range"` — stability-report.py:493, 696, 679). Those files are regenerated on every CI run
(`.github/workflows/stability-full.yml`), not sealed §42 records, so no erratum applies to them; the code fix
below is what corrects them going forward.

**What IS genuinely wrong in all 180 sealed records:** every record's
`configuration_snapshot.fields.custom_constraints.range_touches` is `0`
(`scripts/stability-report.py` `config_opts()`, called from `scripts/prop-search.py:604`, hard-codes
`range_touches=0` into the `bt.OPTS` overlay used for every candidate's scan). This reads as an applied,
meaningful constraint ("require 0 touches of each TR border before a Spring counts" — i.e., "off, but a real
switch"), but `range_touches` was never read by `scripts/backtest-methods.py`'s `scan()` / `simulate()` /
`walk()` at ANY value — confirmed by grep audit 2026-09-28 (four textual references in
`scripts/backtest-methods.py` before this fix: the `OPTS` default, the `--range-touches` argument definition,
the CLI assignment, and one markdown report line — none of them a read inside scan/simulate logic; see
`docs/audits/2026-09-28-method-fidelity.md` §2.3 for the ICT-target-model finding this same audit round made).
The engine would have produced byte-identical trades for every one of these 180 candidates at
`range_touches=1000` as at `range_touches=0`.

## What this does NOT affect

**Every trade, every metric, and every pass/fail verdict in the 180 records is unaffected.** The mislabelling
is in what the snapshot *claims was configured*, not in what the engine *computed*: `range_touches` never
influenced `bt.scan()`'s output at any value, so removing the key changes only how future runs describe their
own configuration, not any number produced by a past run. The 0/180 pass result reported in
`docs/plans/2026-09-28-methodology-improvement-plan.md` §0 stands.

## The fix

- `scripts/backtest-methods.py`: `range_touches` removed from `OPTS`, the `--range-touches` CLI flag, the
  `OPTS.update()` call, and the Vietnamese filter-description line (it had no reader anywhere in the file).
- `scripts/snapshot.py`: `custom_constraints` no longer includes `range_touches`. `setup.ict_target` now
  carries an `ict_target_effective` note (whenever `ict_target` is non-null) stating that
  `scripts/ict-scan.py`'s `setup_candidate()` always targets the −2σ projection first, falling back to the
  dealing-range edge, regardless of the label — the six-way target-model switch this label once named was
  deleted from the engine on 2026-09-13 (`scripts/strategy-runner.py:22`; `scripts/tests/test_live_rules.py`
  `test_ict_target_engine_is_gone`).
- `scripts/stability-report.py`: `--ict-target`'s `choices` are restricted to `["range"]` (its only
  implemented value) rather than offering five choices (`std2`, `std25`, `std4`, `erl_next`, `irl`) the
  scanner has never read since that 2026-09-13 deletion — the flag is kept, truthful, and unchanged in its
  one working case, per A0b's "refuse values the scanner does not implement" option.
- `scripts/tests/test_snapshot_options_have_readers.py` (new): fails if a config-snapshot option name has no
  reader on the scan/simulate path, proven to catch the pre-fix `ict_target`/`range_touches` case.

## Consequence: the dead improve-loop candidate is retired

`docs/architecture/improve-candidates.json` declared `candidates.vol_type.1.override.range_touches: 2`, a
candidate meant to require "two tests of EACH border before a Spring counts" (advance.md 2.11.2). Because
`range_touches` was never read, that candidate was always a no-op indistinguishable from the baseline. It is
removed in the same change. Keeping it would make `scripts/improve-loop.py` refuse it at run time and would fail
`scripts/tests/test_improve_loop.py`'s guard that every override key is a live OPTS key (the `ict_disp`
precedent). The sourced idea itself is NOT dropped: it is recorded as an unimplemented Wyckoff item in
docs/plans/2026-09-28-methodology-improvement-plan.md (W-TOUCH), to be implemented as a real rule and
evaluated there.
